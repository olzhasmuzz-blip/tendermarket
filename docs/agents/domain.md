# Domain docs

## Перед исследованием или изменением домена

- Прочитать корневой `CONTEXT.md`, если он уже создан.
- Прочитать относящиеся к области задачи решения в `docs/adr/`.
- Если документа пока нет, продолжать работу без отдельного предупреждения; создавать доменные документы по мере уточнения понятий и архитектурных решений.

## Структура

Репозиторий использует single-context: один `CONTEXT.md` в корне и общие решения в `docs/adr/`.

## Терминология и решения

- Использовать понятия и названия из `CONTEXT.md`.
- Если нужное понятие не описано, отметить пробел и уточнить модель домена.
- Не менять архитектурное решение молча: если новая работа ему противоречит, явно указать это и предложить пересмотреть ADR.
